# #8319 반영 후 리베이스와 재검증

기준은 `af6bb05b26887135fb9da0fa4e54ca7205564fca`, 리베이스를 완료한 후보는
`0508d3afcdd233b59ea1f0ff04013291d8b0c254`다. 기존 원 PR 20건의 123개 커밋을
유지했고 추가 PR을 체리픽하지 않았다. [커밋 대응](commit-map.json)에서 원 저자를
모두 보존한 것을 확인했다. patch 동일 107개, 새 기준과 결합한 patch 16개다.

## 충돌 해소

- 셀 재조판 함수와 아래 캡션 계산 함수의 공개를 함께 유지했다.
- 도형 삽입은 새 기준의 공통 `reflow_body_inline_object_change`를 사용한다.
- 수식 캐시는 새 기준의 표시 세대별 `document_script::parse`와 구형 저장 프레임을
  유지한다. 구형 저장 프레임 봉인도 캐시 키에 포함하며, 문단 끝 줄간격을 보존했다.
- 표 행 높이 캐시와 정규화된 첫 조각 프레임의 기존 fallback을 함께 유지했다.
- 글꼴 이름 캐시를 사용하면서 PostScript 굵기 접미사의 family·Bold 선택을 유지했다.
- 인라인 줄 정렬과 부동 도형 앵커를 함께 유지했다.
- 중첩 표 원점은 문단/표 소유를 구분하면서 새 기준이 제거한 중복 분기를 복원하지 않았다.
- 그림 줄은 물리 점유 하단으로 수용하며 새 기준의 부호 있는 줄 전진량은 그대로 소비한다.
- 오늘할일의 #8319 항목과 기존 20건 검토 항목을 모두 유지했다.

충돌 보정 스크립트의 실패 뒤 명령이 계속 실행된 중간 시도는 취소했다. 별도로 발견한
도형 파일의 잘림은 새 기준의 동일 원문으로 복구하고 해당 충돌 해소 커밋에 합쳤다.
중간 후보 `c4c4e0e8f`는 검증·제출 후보로 사용하지 않는다.

## 검증 상태

현재 리베이스는 완료됐고 새 기준이 조상이며 미해결 충돌은 없다. suite `--prepare`와
`cargo fmt --all -- --check`를 완료했다. 파생 suite는 커밋하지 않는다.

기존 `faa885e8b` 기준의 67개 조합·956쪽 Native/fresh WASM 및 전체 회귀 결과는
이전 후보의 이력이다. 새 기준의 조판 변경과 결합했으므로 현재 후보의 기능 보존·전쪽
검증 완료로 재표기하지 않는다. 현재 후보의 필수 검증이 완료되기 전에는 push·PR 생성·
머지를 하지 않는다. #8319 후속 처리와 새 PR의 추가 체리픽은 진행하지 않는다.

## 첫 컴파일 검사에서 확인한 결합부 보정

첫 Native Clippy는 exit 101이었다. 자동 적용된 코드도 새 기준의 호출·반환 계약과
일치하지 않을 수 있음을 실제 컴파일로 확인했다.

- 행 높이 캐시는 `Arc<Vec<i32>>`이고 정규화 결과는 `Vec<i32>`다. 각 경로에서
  필요한 행의 높이를 먼저 조회한 뒤 동일한 `Option<i32>`로 fallback을 연결했다.
- 저장 프레임 prefix의 반환형이 `Option`으로 바뀌었으므로 기존 부정 판정은 `None`으로
  반환한다. 내부 소유 판정 closure의 `bool` 반환은 그대로 유지했다.
- 저장 TAC 원점 조회에 실제 다음 문단 `next`를 전달해 기존 표 바깥 상자 등식이
  같은 정보를 소비하게 했다.
- 새 부동 도형 앵커는 글자처럼 표·그림과 달리 가로 분배 폭을 점유하지 않는다.
  기존 부동 표와 함께 정렬 간격의 가시 항목에서 제외했다.

suite·unit-tier 정책은 새 기준을 고정해 통과했다. 기대값·fixture·허용치를 바꾸지
않았다. 위 보정 후 fmt·컴파일 검사와 영향 경계 검증을 계속한다.
