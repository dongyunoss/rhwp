# 중첩 표의 폭 예약과 그림 앵커 소유

Issue: #4138, #1949. 시작 head `fb9be45ce5`, Native150.
앞 단계에서 두 API의 출력 쪽수는 독립 Print와 같은 196쪽이며, 첫 24개 내용 컷도
한컴 재저장 프레임과 같다. 관련 계약 55건·35문서/66쪽 대조군을 통과했다.
이것으로 다음 시각 결함을 면제하지 않는다.

## 22쪽: 다른 표의 폭 예약을 빌린 괘선

새 review·overlay에서 본문 배치는 맞지만 오른쪽 중첩 괘선이 부모 셀 밖으로 나온다.
실제 렌더 트리의 부모 셀은 clip=true인데 bbox 오른쪽이 503.65px까지 확장됐다.
원래 셀 경계는 377.96px이다. 내용 glyph는 기존 부모 경계에서 잘리지만 괘선만
확장된 clip을 소비한다(`fragment-owner-tree-2356/page-022.json`).

`cells_with_ladder_reserved_nested_overflow`는 어떤 표 하나가 자기 저장 폭을
예약하면 셀 전체를 `HashSet<u32>`에 넣는다. 이후 같은 셀의 모든 중첩 표가 그
예약을 사용한다. 현재 원본 문단 288의 표 폭은 31523HU, 자기 저장 줄 폭은
22112HU로 예약을 입증하지 않는다. 하지만 훨씬 뒤의 문단 1517·1606·1719는
44508HU 줄 폭을 가져 같은 셀 전체가 예약된 것으로 분류된다.

기존 #6861 보정 `1f591b5cad`의 원 변경은 `8daf2ce804abb9c60d414a68c7e3fc5c03de491e`,
통합 PR은 #6939다. 원 주장은 해당 표의 호스트 줄이 선언 폭을 품는 경우에만
테두리를 노출한다는 것이다. #5587은 자기 줄이 폭을 예약하지 않는 반대 사례다.
현재 문제는 이 구분을 없앨 이유가 아니라 소유 정보를 보존할 이유다.
다음 수정은 셀·문단·컨트롤과 실제 호스트 줄에 예약을 연결하고, 다른 표나 다른 줄의
폭을 사용하지 않게 한다. 조상 표 사이의 예약 분리와 용지 우단 상한은 유지한다.

## 24쪽: 계산한 그림 앵커를 셀 상단으로 덮어씀

두 번째 그림의 Native bbox는 x=110.18667, y=110.6px이다. 같은 Print 이미지의
96dpi bbox는 약 x=121.37466, y=224.07599px다. PDF의 용지 척도 차이와 별도로
큰 문단 원점 차이가 있다. Native의 호스트 문단 310의 실제 줄 원점은 y=183.64px,
셀 내용 상단은 y=81.24px다. 그림은 2202HU 세로 오프셋과 상·좌 여백 852HU를 갖는다.

`table_partial.rs`는 먼저 `anchor_y`를 현재 조각의 문단 커서에서 구하고
`compute_object_position`에 전달한다. 그런데 뒤의 TopAndBottom 셀 정렬 분기는
continuation이면 저장 vpos를 배제한 뒤 다시 셀 내용 상단을 기준으로 배치한다.
앞에서 구한 문단 앵커가 사라진다. 그림의 좌·상 여백도 deferred band에서만
별도로 추가한다. 해당 원점·여백을 측정·실제 배치의 공통 결과로 연결해야 한다.

기존 문단별 그림 쌓기 #5734는 `19c381dee7`·통합 PR #5811에서 도입됐다.
첫 콘텐츠의 셀 정렬(#2071), 작은 음수 오프셋(#6782), 앞 조각에서 호스트 줄을
소비한 그림 띠, #7840의 호스트 중복 차감과 같은 사례를 함께 대조한다. 어떤
그림이 현재 조각의 호스트 줄을 갖는지와 어디에서 새 프레임을 여는지로 판단하며,
화면 밖으로 나간 결과를 clamp하는 방식으로 대신하지 않는다.

## 물리 점유와 다음 컷

같은 호스트의 두 번째 그림은 높이 13517HU·오프셋 2202HU·위/아래 여백 852HU씩·
아래 캡션 간격 850HU·캡션 줄 높이 1200HU다. 합계 19473HU는 한컴 재저장본의
다음 문단 원점 차이와 정확히 같다. 공통 제어 높이만 읽는 경로는 캡션을 모르고,
deferred 띠 경로는 이전 페이지에서 소진한 오프셋을 별도로 취급한다. 원점 소유와
점유 범위를 구분해야 한다. 현재 빈 호스트 줄의 core 높이만 빼는 추가 띠 계산은
전체 호스트 전진과도 대조한다. 단일 호출에 캡션 높이를 덧붙이는 것으로 끝내지 않는다.
