# OOXML 차트 글줄의 하단 앵커와 범례 가용 프레임

## 원 해결과 독립 근거

원 이슈 #6624 → 기여 #6626 → 실제 통합 #6645의
`b1091864dffee8f8041e5b235d9ab9491ea41c04`를 현재 base/head와 대조했다.
제목14pt·축/범례10pt, 저장 font family와 실제 editable data 소비는 유지한다.
#8064의 legacy WMF/EMF 차트 개선을 이 OOXML 편집 가능 차트의 검증으로 대신하지 않는다.
이전 PR의 IoU·다른 fidelity 지표를 현 raw90% 통과로 바꾸어 보고하지 않는다.

원 실측 주석은 제목의 잉크 하단35.5px를 `baseline`으로 부르고 SVG의 alphabetic y로
넘긴다. 카테고리 라벨도 잉크 하단239.5px를 같은 방식으로 사용한다.621의 실제 HCRDotum
프로그램은 hhea1000em에 descent230이다. Native058 제목 잉크175..191와 독립 Print의
170..187 차이는 줄 하단을 alphabetic 기준선으로 사용한 것과 대응한다. 고정4px 이동이
아니라 SVG의 표준 text-after-edge로 실제 선택한 글꼴의 descent를 소비해야 한다.
usvg의 실제 alignment baseline 경로와 브라우저 SVG 모두 글꼴 기준선을 소비한다.

현재 우측 범례는 plot_y/plot_h 가운데를 사용한다. 그러나 독립 Print의 기본·반 크기·
세로 두 배 프레임은 제목 줄 하단부터 프레임 바닥 사이에 범례를 가운데 놓는다.640에서
제목14pt를 명시한 입력과 상속한 입력이 같은 결과였다. 반 크기 프레임의 독립 가운데
233.763px와 가운데 스와치233.5px, 세로 두 배의421.079px와421px가 대응한다.
기본 프레임도 예측295.4px와 실제 가운데295.5px가 대응한다. 문서 ID·프레임 고정 크기·
눈대중 이동 상수로 조건을 만들지 않는다.

## 실제 소비 경로와 적용 경계

`title_font_px` → 제목 아래끝 앵커/plot 예약 → SVG 제목과 하단 축 라벨 → Native usvg 및
fresh 브라우저 SVG의 실제 글꼴 기준선으로 연결한다. plot 예약의 기존 아래끝 기준은
그대로 두고 표시 기준선만 올바르게 구분한다. 우측 범례는 별도의 가용 프레임을 계산하여
`render_legend_right`에 전달한다. 하단 범례·실제 시리즈 데이터·축 범위·선폭은 건드리지 않는다.
제목 없는 차트는 제목 예약이0이며 전체 프레임에서 우측 범례를 가운데 놓는다.

대조를 먼저 실행한다. 같은 소스의 최적화 fresh에서도 확인한다. 전체 쪽수·전쪽 raw90%와
확대 review/overlay를 모두 확인한 뒤에만 관련 렌더링 회귀를 추가·변경한다. 이미 완료한
표 입력과 #8064 보존 sweep은 동결 producer058/026의 결과로 구분하며 새 소스의 최종
검증을 대신하지 않는다.
